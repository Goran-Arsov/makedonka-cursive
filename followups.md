# Follow-ups — Makedonka Cursive build

Start-of-session brief + what's left. Deep design notes and **every tuning knob** are in
`macedonian-cursive-font-handoff.md` (same folder). The whole font is generated by
`build/scripts/build_font.py` from `build/paths.json` (traced path data) — edit the script's knobs,
never the glyphs by hand. **Connection kerning** is added automatically at the end of each build by
`build/scripts/kern_util.py` (see Current state → Kerning).

## How to work on this (read first — a new session has none of the earlier setup)
- **Build environment** — recreate the Python venv (the earlier one lived in a temp dir and is gone):
  `python3 -m venv .venv && .venv/bin/pip install -r build/requirements.txt`
  (the build needs fonttools, skia-pathops, pillow, numpy, brotli). Run every build script with that python.
- **Iterate loop** — change a knob in `build_font.py` (handoff lists them), build into a **scratch** dir
  (`python build/scripts/build_font.py build/paths.json /tmp/try`), then **verify before shipping**:
  there is no live preview, so render words to a PNG with PIL `ImageFont.truetype(otf, size)` and measure
  with fontTools (`BoundsPen` for glyph bounds / vertical placement, `hmtx` for advance & sidebearings).
  Compare old vs new. **Slant/width is unreliable to measure on round & ornate glyphs** — judge those by eye.
  Note: **PIL does not fully apply GPOS kerning** — to preview the kern, lay out glyphs by hand with the
  GPOS pair values (see the manual-kern render pattern), or open the font in a browser/LibreOffice.
- **Ship a version** — once it looks right, rebuild the whole suite into the project dir:
  1. `build_font.py build/paths.json .`  → Regular `.otf`/`.woff2`/`.woff` + `specimen.png` (auto-adds the kern)
  2. `make_bold.py MakedonkaCursive-Regular.otf . 14`  → Bold (faux-bold dilation; also auto-adds the kern)
  3. `otf2ttf.py <in>.otf <out>.ttf` for each weight  → the two `.ttf`
  4. **bump the version** everywhere: `0.9.N` in `build_font.py` (3 strings) + `make_bold.py` (`VER`),
     the `**Version 0.9.N.**` line in `README.md`, and `?v=NN` in `demo.html` + `makedonka-cursive.css`
  5. zip the 14 entries into `MakedonkaCursive-v0.9.N.zip` (flat top-level `MakedonkaCursive/` folder:
     both weights × otf/ttf/woff2/woff + css + demo + specimen + README + LICENSE)
  6. install for LibreOffice/desktop: copy both OTFs to `~/.local/share/fonts/` then `fc-cache -f`
     (LibreOffice must be fully restarted to pick up a replaced file)
  7. commit (include new files like `build/scripts/kern_util.py`), push, GitHub release, update this file + the handoff
- **Private preview pages (owner-only, not in this repo):** a browser specimen (both `.woff2` embedded as
  base64 `@font-face`, so the kern renders natively) and a non-technical install/use guide exist as private
  shareable pages; the owner holds the links. Regenerate the specimen from the current `.woff2` when the font
  changes. (See Open work #11 — consider committing a specimen source.)

   non-self-intersecting stroker would be crisper. Cosmetic; the solid-fill requirement is met. (Middot `·`
   added in v0.9.16.) **This is also the real/full fix for the FontBakery `overlapping_path_segments` WARN**
   (see "What should still be done → C"): the brush/embolden outlines self-touch at pinch points that no safe
   automated pass can remove — only redrawing with a non-self-intersecting stroker (or hand-drawn forms) clears it.
   **PROTOTYPED 2026-11-01** (offset stroker: offset the centreline by ±r into left/right edges + round caps =
   one clean contour per stroke, same shape as the brush). Result on the digits: near-identical shapes,
   crisper, and **0 real overlap segments** (vs the brush, pre-speck-drop, at 52 by direct count). BUT separate
   strokes leave **hairline junction gaps** where they meet; an endpoint join-disk closes most (4 clean) but
