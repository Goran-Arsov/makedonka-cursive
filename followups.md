# Follow-ups — Makedonka Cursive build

Start-of-session brief + what's left. Deep design notes and **every tuning knob** are in
`macedonian-cursive-font-handoff.md` (same folder). The whole font is generated by
`build/scripts/build_font.py` from `build/paths.json` (traced path data) — edit the script's knobs,
never the glyphs by hand. **Connection kerning** is added automatically at the end of each build by
`build/scripts/kern_util.py` (see Current state → Kerning).

## How to work on this (read first — a new session has none of the earlier setup)
- **Build environment** — recreate the Python venv (the earlier one lived in a temp dir and is gone):
  `python3 -m venv .venv && .venv/bin/pip install -r build/requirements.txt`
  (the build needs fonttools, skia-pathops, pillow, numpy, brotli). Run every build script with that python.
- **Iterate loop** — change a knob in `build_font.py` (handoff lists them), build into a **scratch** dir
  (`python build/scripts/build_font.py build/paths.json /tmp/try`), then **verify before shipping**:
  there is no live preview, so render words to a PNG with PIL `ImageFont.truetype(otf, size)` and measure
  with fontTools (`BoundsPen` for glyph bounds / vertical placement, `hmtx` for advance & sidebearings).
  Compare old vs new. **Slant/width is unreliable to measure on round & ornate glyphs** — judge those by eye.
  Note: **PIL does not fully apply GPOS kerning** — to preview the kern, lay out glyphs by hand with the
  GPOS pair values (see the manual-kern render pattern), or open the font in a browser/LibreOffice.
- **Ship a version** — once it looks right, rebuild the whole suite into the project dir:
  1. `build_font.py build/paths.json .`  → Regular `.otf`/`.woff2`/`.woff` + `specimen.png` (auto-adds the kern)
  2. `make_bold.py MakedonkaCursive-Regular.otf . 14`  → Bold (faux-bold dilation; also auto-adds the kern)
  3. `otf2ttf.py <in>.otf <out>.ttf` for each weight  → the two `.ttf`
  4. **bump the version** everywhere: `0.9.N` in `build_font.py` (3 strings) + `make_bold.py` (`VER`),
     the `**Version 0.9.N.**` line in `README.md`, and `?v=NN` in `demo.html` + `makedonka-cursive.css`
  5. zip the 14 entries into `MakedonkaCursive-v0.9.N.zip` (flat top-level `MakedonkaCursive/` folder:
     both weights × otf/ttf/woff2/woff + css + demo + specimen + README + LICENSE)
  6. install for LibreOffice/desktop: copy both OTFs to `~/.local/share/fonts/` then `fc-cache -f`
     (LibreOffice must be fully restarted to pick up a replaced file)
  7. commit (include new files like `build/scripts/kern_util.py`), push, GitHub release, update this file + the handoff
- **Live specimen** (optional "see it" page): `claude.ai/artifact/BdGyojA5uWSarU4Y8wiK9b` — an HTML specimen
  with both `.woff2` embedded as base64 `@font-face`; browser renders the kern natively. Its source
  (`specimen_src.html`, with `__REG__`/`__BOLD__` placeholders) lives **only in the ephemeral scratch dir**
  and is lost between sessions — recover it by reading the published artifact, then swap in the new base64
  woff2 and republish to the same URL. (See Open work #11 — consider committing the source.)
- **Install & use guide** (public, non-technical): `claude.ai/artifact/3z5jJ3FRbKJa6e4jKD5mQs` — a separate
  shareable page explaining install (Windows/Mac/Linux) + web use. Private; owner shares via the Share menu.

## Current state (v0.9.15 — BUILT into the project dir but NOT yet shipped; 2026-10-31)
- **Ship status: v0.9.15 SHIPPED (2026-10-31).** Project dir has the final Reg+Bold × otf/ttf/woff2/woff +
  `specimen.png`; README + `?v=26` bumped; `MakedonkaCursive-v0.9.15.zip` built; both OTFs installed to
  `~/.local/share/fonts/` (+ fc-cache; restart LibreOffice to pick them up); committed + pushed to `main`
  (`build/scripts/kern_util.py` now tracked); GitHub **release v0.9.15** cut with the zip; live specimen
  artifact updated. amici still NOT updated (below).
- **Coverage — 146 glyphs:** all 31 Macedonian Cyrillic letters (upper+lower), plus the grave-accented
  **ѐ/ѝ** (U+0450/U+045D); a full **Latin** alphabet A–Z/a–z (drawn letters + de-skewed copies of Cyrillic
  sources — `LATIN_HOMO` is empty, so no Latin letter shares a Cyrillic glyph); digits 0–9 (equal height);
  punctuation incl. Latin "up" quotes `“ ” ‘ ’` and Macedonian `„ "`. (No middot `·` glyph — minor gap.)
- **Weights:** Regular + Bold (Bold is a faux-bold dilation via `make_bold.py`).
- **Kerning (NEW, v0.9.15):** the font now carries a **GPOS `kern` feature on BOTH weights**, auto-generated by
  `build/scripts/kern_util.py` (imported + called by `build_font.py` and `make_bold.py`, so each weight is
  kerned on its own metrics — Bold's dilated glyphs need different values). It is **bidirectional connection
  kerning**: per within-script lowercase pair it measures the white area + nearest approach, then LOOSENS
  crowded pairs (n–k…) up toward `W_LOW` and TIGHTENS loose joins (о–н…) down toward `W_HIGH`, never past the
  nearest floor `N_FLOOR` (so a tighten can't collide). It is **algorithmic, not hand-kerned** (params at the
  top of `kern_util.py`). Counts: Regular **609** pairs, Bold **439**. The old "spacing-only, no GPOS" is gone.
- **Spacing base:** band-based sidebearing spacing (per-letter), with the GPOS kern on top. No `GSUB`/`calt`
  (no contextual substitution) — true entry/exit joining is still v2 (Open #3), but the kern reads connected.
- **Size:** `UPM=700`, so it renders at a normal-font size for a given point size (caps ~1.2× DejaVu,
  x-height ~0.67×). Line height is tall (flourishes) — set fixed line spacing in the app if needed.
- **amici: NOT updated (the user's step).** amici still ships the OLD v0.9 files and does not display the
  font anyway (`--font-script` switched to Nunito in an uncommitted refactor; `font-makedonka` defined but
  used in no view). The visible CC BY-SA credit IS present in amici's public footer. Don't re-enable the
  font on the site without asking — removal looks intentional. *To display it there (re-verify against
  amici's current code first):* copy the current woff2/woff to amici `public/fonts/`, bump `?v=` in
  `app/assets/tailwind/application.css`, run `bin/rails tailwindcss:build`, and set
  `config.x.script_font = :makedonka` (the opt-in flag; `ApplicationHelper#makedonka_font?` adds `.script-makedonka`).

## Changelog (one line each; details + knobs are in the handoff)
- **v0.9.15** — **connection kerning** (GPOS, both scripts & both weights, bidirectional — loosen crowded,
  tighten loose; auto via `kern_util.py`); Latin **d** bowl widened + spacing evened (`LAT_RSP["d"]=-7`);
  Latin **i** side space cut 63→23 (`LAT_SPACE["i"]` 55→15 — floating fixed); Cyrillic **р/ј** re-centred on
  the x-height body so the far-left descender no longer shoves the body right (`BODY_LSB`); small Latin **k**
  left sidebearing tucked in 8→2 (`LAT_LSP["k"]=-6`). *Design note:* trimming the Latin exit hairs was built

## Open / optional work (pull on demand)
1. **Contrast match for drawn Latin** — the reused *copies* carry the Cyrillic high thin/thick contrast
   while the *drawn* letters are more even. Thin the drawn hairlines (`LW_DMIN`) to match, if wanted.
2. **Short caps `C` / `E` (and drawn `G`/`L`)** — `C.lat`/`E.lat` sit a touch short (their Cyrillic source has a
   bottom swash that defeats a `BASEFRAC` baseline lift — it overshoots); drawn `G`/`L` are short by their own
   design. Would need those specific caps redrawn (not a global knob). Minor. (Round cap `О` was equalized in v0.9.11.)
3. **True contextual joining (v2)** — real entry/exit connectors + `GSUB`/`calt`. Big, uncertain on traced
   standalone forms. **Lower priority now** — the v0.9.15 GPOS kern already makes joins read connected (it
   pulls each letter into contact without morphing strokes). Full joining would still be cleaner; likely needs Glyphs/FontForge.
4. ~~**Pair kerning (`GPOS`)**~~ — **DONE in v0.9.15** (bidirectional auto-kern, both scripts & weights via
   `kern_util.py`). Could still be hand-refined for individual pairs, or extended to uppercase/mixed pairs,
   but the lowercase rhythm + connections now read well. Tune via the params in `kern_util.py`.
5. **Even consecutive capitals (`RIGHT_CAP`)** — would trim right cap-flourishes for all-caps, but
   reduces the lowercase tuck-under the user approved. Only matters for all-caps (not this font's use).
