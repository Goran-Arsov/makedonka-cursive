- **Baseline (v0.3):** per-glyph alignment — each glyph is placed on y=0 by its
  own **body bottom** (raster: lowest row whose horizontal ink extent is wide),
  which excludes descender tails and handles round overshoot. This replaced a
  per-row baseline that was **descender-biased** (rows heavy with descenders
  floated their letters up → words wandered). Detector-failing letters use a
  manual fraction in `BASEFRAC` (Ј=0.30, ј=0.42 top-heavy; д=0.50 wide g-loop;
  з=0.31 was floating with its descender lost; **Р=0.0, Ч=0.0** rest on baseline —
  their thin stems fooled the detector into putting the baseline at the bowl,
  making them float/shrink); digits align by ink bottom. If a letter sits off the
  line, tune `BASEFRAC` (higher = sits lower).
- **Per-glyph size/overhang (v0.8):** `SCALE_OVERRIDE` shrinks glyphs drawn
  oversize in the source (Ф=0.82, з=0.76, ѕ=0.78). `LEFT_CAP` (220) limits a glyph's
  leftward
  ink overhang past the join band — needed for caps whose bottom is offset from
  their body (Ч's bowl juts left of its narrow base), else they crash the previous
  word and get a collapsed advance.
- **Chart display only (not font metrics):** the bare capital *chart* can't space
  evenly off advances (ornate caps have wildly varying flourish overhang → gaps or
  crossings). Both the specimen (`line_caps`/`_body_edges` in `build_font.py`) and
  `demo.html` position caps by **even dense-body spacing**: each cap's body is found
  by ink-mass percentile (14–86%) and bodies are set a constant `GAP` (~0.44em)
  apart; flourishes cross as they naturally do. For `demo.html` the per-cap
  `margin-left` values are generated by `scripts/genchart.py`. This is display-only;
  the font metrics are for real words (one-capital words), unchanged.
- **Spacing (v0.6):** side bearings are measured in the **x-height join band**
  (`CONN_LO..CONN_HI`, relative to the glyph's baseline), not from the full-height
  body. Cursive joins at the x-height; a capital's tall flourishes sit *above* the
  band, so they no longer inflate its advance — the next lowercase tucks under the
  flourish and the word reads whole. Margin is `M_BODY` (default 8, `build_font.py`
  arg 3); mass-based body (`BODY_TRIM`) is the fallback when the band is empty;
  digits keep mass-based spacing. **Trade-off: consecutive capitals overlap** (the
  band tucks each following glyph fully under the previous capital), so the font is
  for one-capital words, not ALL-CAPS — the specimen/demo show the caps spaced out.
  Lower `M_BODY` to tighten joins, raise to loosen; widen the band to change what
  counts as the join height. Earlier tries (mass-trim `BODY_TRIM`, then height-based
  body) failed because bbox overlap ≠ overlap at the join height. Not pair-kerned.
- **Digits (v0.2, strokes reworked v0.9):** calligraphic pen strokes with a
  broad-nib width model (thick downstrokes) sheared 18°, unioned so loops form
  counters. Centrelines `D0..D9`; weight via `WMAX_SCALE`/`WMIN_SCALE`. Strokes
  are now drawn with a **disk brush** (`_disk` along a uniformly `_sample`-d
  centreline, `ribbon_open`/`ribbon_oval`), NOT an offset outline: the old outline
  self-intersected on tight inner curves and the nonzero fill left **white slivers
  inside the stroke**. Disks never fold/flip winding → always solid. Needs dense
  uniform sampling (`step≈6`) or the hairlines break into dots.
- **Weight tweak:** `EMBOLDEN` (cp→amount) faux-bolds a glyph (union with nudged
  copies). Used for ѕ=9, which read too thin after its `SCALE_OVERRIDE` shrink.
- **Per-glyph point remap (v0.9.1):** `POINT_SHIFT` (cp→function) rewrites a glyph's
  raw traced points *before* the scale/flip, via `ShiftPen`. Used only for **Н**
  (`_n_body_shift`) to stop it colliding with К: (1) flatten the crossbar toward
  horizontal — a weighted vertical shear in the stem gap, `N_FLATTEN`/`N_XOVER`
  (`N_XOVER` drives the bar into the right stem so pathops' nonzero union heals the
  junction; past ~0.45 a junction nub appears); (2) trim the two top flourishes —
  radial shrink toward their bases, `N_TRIM_R` (right swoosh) / `N_TRIM_L` (left curl).
  All bands are in paths.json coordinate space for path idx 40, so they'd need
  re-tuning if `layout.py` re-extracts the paths. `paths.json` itself is untouched.
- **Punctuation (redesigned v0.9.1):** calligraphic, 18°-slanted marks in the disk-brush pen
  style, replacing the old geometric shapes. Helpers: `ribbon_dir` (direction-weighted ribbon,
  for the ? hook), `ribbon_prof` (explicit-taper ribbon, for ! and the pen-commas), `_oval`
  (slanted dots), `_pencomma` (teardrop comma; `up=True` = raised "6" form). `_make` draws the
  mark upright, applies SLANT, then centres the ink in the advance; colon/semicolon upper dots
  are pre-shifted −SLANT·Δy so they stack vertical after slant. Edit the `PUNCT` table to tune.
- **Bold weight (v0.9.1):** `build/scripts/make_bold.py` makes `MakedonkaCursive-Bold.*` from the
  Regular OTF. Faux-bold (traced letters can't be redrawn heavier): each glyph dilated by an
  8-direction union (amount `D`, default 14), advance +2D, shifted +D to keep the left
  sidebearing, rebuilt via FontBuilder, tagged weight 700 / `fsSelection` BOLD, same family name
  as Regular so they pair. `embolden` falls back to the un-simplified union if `pathops.simplify`
  fails on a dense glyph. Bigger `D` = heavier but counters start to fill. Run it after
  `build_font.py`: `make_bold.py <Regular.otf> <outdir> [D]`.
- **Latin alphabet (v0.9.2):** full A–Z/a–z, in the `# Latin` section of `build_font.py`.

  outlines; incl. g=д, u=и, m=м). `LATIN_DRAWN` holds the 26 drawn letters with no look-alike

  drawn via `_L_x`/`_U_X` functions (ribbon_dir/ribbon_prof/_oval + `_loopasc`/`_lbowl`/
  `_archright` helpers) at LXH=247/LASC=553/LCAP=653/LDESC=-240, slanted 18°, spaced by the
  x-height band (`_latin_sb`) with baseline 0. The clean-arch trick (n, h): the up-stroke

  intentionally restrained (companion to the ornate Cyrillic caps). Edit a letter = edit its

## Goal

Create my own **Macedonian** cursive Cyrillic font(s), in two versions:

- **v1 — standalone / disconnected cursive letters.** Each glyph is
  cursive-*styled* but sits on its own; no joining strokes run between letters.
  Build this first: it solves the letter *shapes* without the connection
  problem layered on top.
- **v2 — fully connected.** Reuse v1's shapes, add entry/exit strokes at a
  shared join height, and optionally OpenType contextual alternates (`calt`)
  for natural joining. v1's work carries straight into v2.

Coverage: **Macedonian only** to start (31 letters). Extra Cyrillic
(Russian/Serbian/Bulgarian/Ukrainian) can be added to the same font file later.

## ⚠️ The one thing that matters most: Macedonian cursive ≠ Russian cursive

Macedonian cursive letterforms follow the **Serbian** tradition, **not** the
Russian one. Several lowercase letters have cursive/italic shapes that differ
from what a Russian-trained hand draws. **If you use Russian cursive habits,
a Macedonian reader will find it wrong.** This is a well-documented
localization problem, not a nuance.

Letters whose cursive form differs from Russian: **б, г, д, п, т** (and
sometimes **и, ш**). Known distinctive forms:

| Letter | Macedonian / Serbian cursive form |
|--------|-----------------------------------|
| **д**  | single-storey Latin **g** shape (sourced — see refs) |
| **п**  | like a Latin **u** with a bar/macron on top `[VERIFY exact shape against a MK reference]` |
| **т**  | like a Latin **m** with a bar/macron on top `[VERIFY exact shape against a MK reference]` |
| **г**  | distinct Serbian-style form (not Russian cursive г) |
| **б**  | distinct Serbian-style loop form |

→ **Lock exact shapes from a Macedonian handwriting reference**, not a Russian
one. Search: `македонски ракописни букви`, `македонска школска пропис`, or the
MK education ministry's handwriting materials.

**Good news:** because this is a *Macedonian-only* font, you do **not** need the
OpenType `locl` (localized-forms) machinery that mixed Russian/Macedonian fonts
require — just draw the Serbian-style forms as the **default** glyphs.

## Tooling

- **FontForge** — free, open-source, runs on Linux (the dev box here). Dated UI,
  fully capable, handles OpenType `calt`/ligatures for v2. **Recommended.**
- **Glyphs** — Mac only, paid; best-in-class for connected scripts (v2). Use if

## Drawing-method decision — v1 resolved (traced SVG); still relevant for v2

v1 was built by **tracing the SVG** (no hand-draw or from-scratch vector was
needed). The tradeoff below applies only to a possible redraw or to the v2
connected forms.

Two methods exist and are **separate source workflows** — glyphs don't transfer
cleanly between them, so "both methods × both versions" ≈ 4× the drawing work:

- **Hand-drawn + scanned** — fast, personal, but weak on precise Serbian-style
  forms; dead-end for v2.
- **Vector in software** — more control; v2 needs vector editing anyway.

**Recommendation: vector-only for v1** (in FontForge). Decision not yet
confirmed by the user — confirm at the start of the next session.

## First concrete steps (reference — if redrawing from scratch, or for v2)

1. Get a Macedonian cursive reference; sketch the full lowercase set on paper —
   especially **д, п, т, ѓ, ќ, ѕ** — to lock forms before touching software.
2. In FontForge: set up the font (UPM 1000, baseline, x-height, cap height).
3. Draw **о, н, и, л** first — they set proportions and rhythm.
4. Draw the Macedonian-specific **ѓ, ќ, ѕ, ј, љ, њ, џ**, then the rest of lowercase.
5. Test word with tricky forms: **патот**, **дете**, **ѓердан** — fix spacing.
6. Add uppercase, digits, punctuation → export `.otf`.
